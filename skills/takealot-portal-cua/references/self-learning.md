# 自我学习手册（遇到新东西时，怎么学、怎么验证、写回哪里）

> 目标：让这套技能**越用越准**，而不是"每次都从零查一遍"。
> 核心纪律：**任何结论都必须有一个"最强判据"的实测**才准写回文档——平台侧数据 > 页面状态 > 记忆。

## 0. 学习闭环（五步，缺一步都不算学过）

```
① 复现（能稳定看到问题）
   ↓
② 取证（拿到平台/服务端/日志的硬证据，而不是"看起来对"）
   ↓
③ 最小验证（写一个 20-50 行的探针脚本，只验这一个假设）
   ↓
④ 写回（写进对应的文件，带证据与日期）
   ↓
⑤ 复验（照新文档跑一遍，确认别人照做也能得到同样结果）
```

## 1. 什么信号触发"该学了"

| 触发 | 该学什么 |
|---|---|
| `discover_fields.py` 输出的字段数与上次 manifest 不一致 | 平台改版：字段增删/改名/变必填 → §3 重学流程 |
| 同一个症状**第二次**出现 | 它不是偶发 → 写进 `pitfalls.md` |
| 某一步耗时比基准 **+50%** 以上（基准见下） | 平台变慢/我们的快路失效 → 实测后回填数字 |
| 平台出现**没见过的新拒因/新文案** | 记下原文 + 出现条件 → `pitfalls.md`（含"它到底在说什么"的判据） |
| 新类目 / 新商品类型要上 | 字段清单 + 下拉真实选项 + facts 模板 |
| 客户机报的错与我们文档不符 | **文档错**优先怀疑：按 §0 复现，改文档 |

**当前基准（2026-09-26，Intel Mac + Chrome + 纯 bsk，25 字段 + 543 字描述 + 8 图）**：
单条 **340.7s**（新建页 12.5s / 类目变体 13.7s / 属性 42.6s / 富文本 ~110s / 图片 ~227s / 分区+断言 7.8s / 预览 6.4s / Submit 29.3s）。

## 2. 怎么"实测一条新路"（防幻觉的硬流程）

1. **先写判据，再写代码**：明确"什么叫成功"。富文本类 = 服务端回读；写值类 = 页面读回 + `data-error`；
   提交类 = submissions 表新增一行。**不接受"页面看起来成功了"**。
2. **一次只改一个变量**：换输入路就只换输入路，别同时改等待时间/选择器。
3. **用最小探针**，不要跑全流程验证一个点（全流程 6 分钟，探针 1 分钟）。
   现有探针可参考/复用：`probe_synth_persist.py`（**页面内合成事件为什么不持久**）、
   `verify_title_paste.py`（OS 粘贴兜底在本机可不可用）、`verify_persisted.py`（**服务端回读 = 唯一判据**）。
4. **留下反证**：也要记录"什么条件下它不work"（例：`bsk press Backspace` 在本平台无效）。
5. 结论必须能和数字对上：写进文档时带上**长度/次数/耗时**（如"477/477"、"152 ms/字"）。

## 3. 重学流程（平台改版 / 换新类目）

1. `python3 scripts/discover_fields.py "<类目1>" "<类目2>" "<叶子>"` → 真字段清单（`data-fieldid`/必填/控件类型/标签），自动落 `manifests/`。
2. 与上次清单**逐条比对**：新增、改名、必填变化。
3. 按新清单写 facts（参考 `templates/`），**先 `--no-submit` 跑到 `clean: true`**。
4. 再跑带提交，核对 submissions 表新增行（In Review）。
5. 把字段清单留在 `manifests/`、坑写进 `pitfalls.md`、facts 进 `templates/`。

## 4. 写回哪里（做完必须落一处，别只留在对话里）

| 学到什么 | 写到哪 | 必须带的证据 |
|---|---|---|
| 新症状 / 新拒因 | `references/pitfalls.md` | 原文文案 + 出现条件 + 最终判据 |
| 输入路的新发现（哪条持久/哪条不持久） | `references/rich-input-routes.md` | 长度比对（期望 vs 实测）+ 是否回读服务端 |
| 类目字段与选项 | `manifests/fields_<slug>.json`（脚本自落） | 不改手写 |
| 可复用 facts | `templates/facts_*.json` | 参数化：字段名可换、值可换 |
| 引擎改进 | `scripts/tl_engine.py` | 注释写清"为什么"（源自哪个坑）+ 失败即停 |
| 平台机制结论（如"条码留空=平台生成"） | `SKILL.md` 对应章节 | 一句话 + 实测证据 |
| 耗时/吞吐基准 | 本文件 §1 的基准表 + `SKILL.md` 实测表 | 分段计时（`TIMER` 行） |
| 退步/回滚的新经验 | `references/rollback.md` | 会丢什么 + 退到什么状态算干净 |

**不写**：账号/操作者身份、登录凭据、客户商品数据、一次性调试路径、"今天改了 X"这类过程叙事。

## 5. 自测：改完文档怎么知道没写错

- 照文档里的命令**原样跑一遍**（不要凭记忆补参数），确认输出与文档描述一致。
- 若文档里写了一个数字（"约 6 分钟"/"152ms/字"），顺手用一次实测或日志复核；**对不上就改文档，不要改日志**。
- 把这次学习的**日期**写进条目（平台的实现会变，日期是这条结论的保质期标签）。
